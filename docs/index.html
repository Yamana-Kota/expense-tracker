1. プロジェクト概要

Auto Expense は、家計・支出を管理するWebアプリです。 レシートを撮影してAIで自動読み取りしたり、手動でカレンダーに収入・支出を記録したり、 グラフで収支の傾向を分析できるツールを目指しています。

🎯 主な機能（現時点）

  • 🔐 Amazon Cognito 認証 — NextAuth.js v5 を使った OAuth ログイン。未認証ユーザーはミドルウェアでダッシュボードへのアクセスをブロック
  • 📅 カレンダー形式の手動入力 — 日付を選択して収入/支出を登録・削除。上部に月次サマリーカード（支出・収入・収支）を表示
  • 📊 分析グラフ — カテゴリ別支出・月別推移・資産推移を可視化
  • 🧾 レシート登録UI — プレースホルダー（機能はこれから実装）
  • ⚙️ 設定 — Coming Soon
ℹ️

現時点ではデータはブラウザのメモリ上にのみ存在します。ページをリロードするとデータはリセットされます（バックエンド未実装）。

5. ルーティング（Next.js App Router）

Next.js の App Router では、フォルダ構造 = URLの構造になります。

ファイルURL説明

middleware.ts によるルート保護

middleware.ts はリクエストがページに到達する前に実行されます。 /dashboard 配下へのアクセス時にセッションを確認し、 未認証のユーザーはトップページ（/）へリダイレクトします。 

// middleware.ts
import { auth } from '@/auth'
import { NextResponse } from 'next/server'

export default auth((request) => {
  if (!request.auth) {
    return NextResponse.redirect(new URL('/', request.url))
  }
})

export const config = {
  matcher: ['/dashboard/:path*'],  // このパターンにマッチするURLにのみ適用
}

6. 状態管理（useState）

このアプリは外部の状態管理ライブラリ（ReduxやZustandなど）を使わず、 Reactの useState フックだけで状態を管理しています。 各コンポーネントが自分に必要な状態だけを持ちます。

DashboardPage の状態

// app/dashboard/page.tsx
const [activeTab, setActiveTab] = useState<Tab>('manual')
//         ↑現在選択中のタブ名  ↑更新関数         ↑初期値は 'manual' タブ
📖

useState<Tab> の <Tab> はTypeScriptのジェネリクス（型パラメータ）です。 この状態が Tab 型の値しか持てないことを宣言しています。

ManualEntryTab の状態一覧

状態名型役割
currentMonthDateカレンダーに表示している月
selectedDatestring | null選択中の日付（"2026-03-20" 形式）
showFormboolean入力フォームを表示するか
entriesEntry[]登録済みの収支エントリ一覧
entryTypeEntryType入力中のエントリが支出か収入か
categorystring選択中のカテゴリ（食費・交通費など）
amountstring入力中の金額（文字列として管理）
notestringメモ欄の内容
⚠️

なぜ金額を string で管理するの？
HTMLの <input type="number"> は値を文字列として返します。 ユーザーが何も入力していない場合は ""（空文字）になります。 これを number で管理しようとすると、空欄の表現が難しくなるため、 入力中は string で管理し、保存時に Number(amount) で数値に変換します。

7. データフロー（手動登録の例）

ユーザーが支出を登録するまでの流れを追ってみます。

👆 ユーザーがカレンダーの日付をクリック
↓
DayCell の onSelect コールバックが呼ばれる
📅 setSelectedDate(dateStr) が実行される
↓
Reactが再レンダリングを行う
📋 選択日のエントリ一覧とフォームが表示される
↓
ユーザーが金額・カテゴリを入力して「保存」ボタンを押す
💾 handleSave() が buildEntry() で Entry オブジェクトを作成
↓
setEntries([...entries, newEntry]) でステートを更新
🔄 再レンダリング → カレンダーのマスに金額が表示される
// handleSave の中身（簡略版）
function handleSave() {
  if (!selectedDate || !amount) return  // 未入力チェック

  const newEntry = buildEntry({
    entries,
    date: selectedDate,
    type: entryType,
    category,
    amount: Number(amount),   // 文字列 → 数値に変換
    note,
  })

  setEntries([...entries, newEntry])  // 配列を新しく作って更新（イミュータブル）
  setAmount('')   // フォームをリセット
  setNote('')
}
💡

イミュータブル（不変）な更新： [...entries, newEntry] は「既存の配列に要素を追加した新しい配列を作る」書き方です。 entries.push(newEntry) のように元の配列を直接変更してはいけません。 Reactは「参照が変わったかどうか」で再レンダリングを判断するため、 元の配列を変更しても変化を検知できないからです。

「追加」ボタンを押したときの流れ

👆 ユーザーが「追加」ボタンをクリック
↓
handleShowAddForm() が呼ばれる
📝 setShowForm(true)、フォームの各フィールドを初期値にリセット
↓
Reactが再レンダリング → showForm === true なので入力フォームが表示される
🔘 支出/収入ボタンを押すと handleSelectExpense / handleSelectIncome が呼ばれる
↓
setEntryType と setCategory(resolveDefaultCategory(...)) でカテゴリも自動で切り替わる
⌨️ 金額を入力するたびに handleAmountChange → setAmount(event.target.value)
↓
金額が空か 0 以下のとき「保存」ボタンは disabled になり押せない
💾 「保存」ボタンを押す（または Enter）→ handleFormSubmit → handleSave
↓
buildEntry(...) でエントリオブジェクトを生成 → setEntries([...previous, entry])
🔄 再レンダリング → カレンダーのマスに金額が反映され、フォームが閉じる

エントリを削除したときの流れ

🗑️ EntryRow の削除ボタンをクリック
↓
EntryRow 内の handleDelete() が呼ばれる（useCallback でメモ化済み）
📡 onDelete(entry.id) でIDを親（ManualEntryTab）へ伝える
↓
ManualEntryTab の handleDeleteEntry(id) が受け取る
🔧 setEntries(previous => previous.filter(e => e.id !== id))
↓
そのIDを除いた新しい配列で state が更新される
🔄 再レンダリング → エントリ一覧から行が消え、カレンダーの金額も更新される

タブを切り替えたときの流れ

🖱️ ユーザーがタブボタン（例:「グラフ」）をクリック
↓
TabButton 内の handleClick() が呼ばれる
📡 onSelect('analytics') で id を親（DashboardPage）へ伝える
↓
DashboardPage の handleTabSelect(id) が setActiveTab('analytics') を呼ぶ
🔄 再レンダリング → activeTab === 'analytics' が true になり AnalyticsTab が表示される
↓
他のタブはアンマウントされる（&& 演算子 で false になるため）
🎨 選択中タブのボタンは isActive === true でアクティブなスタイルになる

前の月・次の月ボタンを押したときの流れ

⬅️ 「前の月」ボタンをクリック
↓
handlePrevMonth() が呼ばれる
📅 setCurrentMonth(prev => new Date(prev.getFullYear(), prev.getMonth() - 1, 1))
↓
month が 1 つ減った新しい Date オブジェクトで state が更新される
🔄 再レンダリング → カレンダーのグリッドが再計算されてその月の日付が並ぶ
↓
getMonthlyTotals もその月で再計算され、上部サマリーカードの金額が変わる
🔒 「次の月」ボタンは isMaxMonth === true になると disabled が付いて押せなくなる

9. Header コンポーネント

components/Header.tsx クライアントコンポーネント

アプリ上部に表示されるナビゲーションバーです。useSession で認証状態を取得し、ログイン済みのときは「ログアウト」ボタン、未ログインのときは「ログイン」ボタンを表示します。

表示内容

  • 左側：レシートアイコン＋「Auto Expense」のロゴ文字（/dashboard へのリンク）
  • 右側（認証済み）：「ログアウト」ボタン → signOut({ callbackUrl: '/' })
  • 右側（未認証）：「ログイン」ボタン → signIn('cognito', { callbackUrl: '/dashboard' })
📖

なぜクライアントコンポーネントにするの？
useSession（next-auth/react）はブラウザ上でセッションを取得するフックです。 フックはクライアントコンポーネントでしか使えないため、'use client' が必要です。 

'use client'

import { useSession, signIn, signOut } from 'next-auth/react'

export default function Header() {
  const { status } = useSession()  // 'loading' | 'authenticated' | 'unauthenticated'

  const handleSignIn = useCallback(() => {
    void signIn('cognito', { callbackUrl: '/dashboard' })
  }, [])

  const handleSignOut = useCallback(() => {
    void signOut({ callbackUrl: '/' })
  }, [])

  return (
    <header>
      <Link href="/dashboard">
        <Receipt />
        <h1>Auto Expense</h1>
      </Link>

      {status === 'authenticated' && (
        <button onClick={handleSignOut}>
          <LogOut /> <span>ログアウト</span>
        </button>
      )}
      {status === 'unauthenticated' && (
        <button onClick={handleSignIn}>
          <LogIn /> <span>ログイン</span>
        </button>
      )}
    </header>
  )
}

9b. 認証システム

auth.ts — NextAuth 設定

auth.ts サーバーサイド

NextAuth.js v5 の設定ファイルです。Amazon Cognito を OAuth プロバイダーとして登録し、 handlers・auth・signIn・signOut をエクスポートします。 

import NextAuth from 'next-auth'
import Cognito from 'next-auth/providers/cognito'

export const { handlers, auth, signIn, signOut } = NextAuth({
  providers: [
    Cognito({
      clientId:     process.env.COGNITO_CLIENT_ID!,      // 環境変数から取得
      clientSecret: process.env.COGNITO_CLIENT_SECRET!,
      issuer:       process.env.COGNITO_ISSUER!,
    }),
  ],
  pages: {
    signIn: '/',  // 未認証時のリダイレクト先
  },
})
💡

なぜシークレットを直書きしないの？
API キーやシークレットをソースコードに書くと、リポジトリ経由で漏洩するリスクがあります。 process.env.XXX を使って環境変数から読み込み、値は .env.local（gitignore 済み）に保存します。

app/api/auth/[...nextauth]/route.ts — API ルートハンドラー

app/api/auth/[...nextauth]/route.ts

auth.ts からエクスポートした handlers を Next.js の Route Handler として登録します。 これだけで /api/auth/callback/cognito などのエンドポイントが自動生成されます。 

import { handlers } from '@/auth'

export const { GET, POST } = handlers
📌

[...nextauth] の意味： Next.js の「キャッチオールルート」です。 /api/auth/ 以降のパスをすべて1つのファイルで受け取れます。 /api/auth/signin や /api/auth/callback/cognito など NextAuth が使う複数のパスを一括で処理します。

Providers.tsx — SessionProvider ラッパー

components/Providers.tsx クライアントコンポーネント

App Router ではレイアウト（layout.tsx）がサーバーコンポーネントになるため、 クライアントコンポーネントである SessionProvider を直接書けません。 そこでこのファイルに切り出し、layout.tsx からインポートします。 

'use client'

import { SessionProvider } from 'next-auth/react'

export default function Providers({ children }: { children: React.ReactNode }) {
  return <SessionProvider>{children}</SessionProvider>
}

SignInButton.tsx — Cognito サインインボタン

components/SignInButton.tsx クライアントコンポーネント

ランディングページ（app/page.tsx）に表示するサインインボタンです。 page.tsx はサーバーコンポーネントなので、onClick を持つボタンをこのファイルに分離しています。 クリック時に signIn('cognito') を呼び出して Cognito の認証フローへ遷移します。 

'use client'

import { signIn } from 'next-auth/react'

export default function SignInButton() {
  const handleSignIn = useCallback(() => {
    void signIn('cognito', { callbackUrl: '/dashboard' })
    // callbackUrl: 認証完了後にリダイレクトするURL
  }, [])

  return <button onClick={handleSignIn}>ログイン</button>
}
💡

void signIn(...) の意味： signIn は Promise を返しますが、ここでは await せず即座に画面遷移が始まります。 void を付けることで「返り値（Promise）を意図的に無視している」ことを明示し、 ESLint の no-floating-promises ルールを満たします。

10. TabButton コンポーネント

components/TabButton.tsx クライアントコンポーネント

タブナビゲーションの1ボタン分を担当するコンポーネントです。 ユーザーがボタンをクリックすると、コンポーネント内の handleClick が呼ばれます。 そこから onSelect(id) を通じて親の DashboardPage へIDが伝わり、 handleTabSelect が setActiveTab(id) を実行します。 その結果 activeTab が更新されて再レンダリングが走り、対応するタブコンテンツが表示されます。

また、isActive props の値によってボタンのスタイルが変わります。 activeTab === id が true のタブボタンだけ isActive が true になり、 アクティブなスタイル（青いアンダーライン等）が適用されます。

labelstringボタンに表示するテキスト（"レシート登録" など）
iconLucideIcon表示するアイコンコンポーネント
isActivebooleanこのタブが選択中かどうか

/**
 * タブナビゲーションの各ボタン
 * @param properties - タブの識別子・ラベル・アイコン・状態・コールバック
 */
export function TabButton({ id, label, icon: Icon, isActive, onSelect }: TabButtonProps) {
  // useCallback: onSelect が変わらない限り関数を再生成しない（最適化）
  const handleClick = useCallback(() => {
    onSelect(id)
  }, [id, onSelect])  // ← id か onSelect が変わったら再生成

  return (
    <button
      onClick={handleClick}
      className={isActive ? 'tab-nav__button--active' : 'tab-nav__button--inactive'}
    >
      <Icon size={16} />   {/* icon プロパティを Icon という大文字変数に代入してJSXで使う */}
      <span>{label}</span>
    </button>
  )
}

カレンダーの構築ロジック

カレンダーのグリッドは以下の手順で構築されます。

月次サマリーカード（ManualEntryTab 上部に表示）

ManualEntryTab の上部には「支出・収入・収支」の3枚のサマリーカードが表示されます。 これは 実際に登録したエントリをリアルタイムで集計しています。 AnalyticsTab の SummaryCards コンポーネント（固定モックデータ）とは別物です。 

/**
 * 指定した年月のエントリから支出合計と収入合計を計算する
 * @param entries - 全エントリの配列
 * @param year - 年
 * @param month - 月（0始まり）
 * @returns 支出合計と収入合計を持つオブジェクト
 */
function getMonthlyTotals(entries: Entry[], year: number, month: number) {
  const prefix = `${year}-${String(month + 1).padStart(2, '0')}`
  // "2026-03" で始まるエントリだけ取り出す
  const monthEntries = entries.filter((entry) => entry.date.startsWith(prefix))
  return {
    expense: monthEntries.filter((e) => e.type === 'expense').reduce((sum, e) => sum + e.amount, 0),
    income:  monthEntries.filter((e) => e.type === 'income').reduce((sum, e) => sum + e.amount, 0),
  }
}

/**
 * サマリーカード用に金額を整形する（1万円以上は「万円」単位）
 * @param amount - 金額（円）
 * @returns "12.7万円" や "3,200円" 形式の文字列
 */
function formatSummaryAmount(amount: number): string {
  if (amount >= 10000) return `${parseFloat((amount / 10000).toFixed(1))}万円`
  return `${amount.toLocaleString()}円`
}

// コンポーネント内で集計し、カードに渡す
const { expense: monthlyExpense, income: monthlyIncome } = getMonthlyTotals(entries, year, month)
const monthlyBalance = monthlyIncome - monthlyExpense

// 収支がプラスなら緑、マイナスなら赤のカード背景
<div className={`rounded-2xl px-4 py-3 ${monthlyBalance >= 0 ? 'bg-green-50' : 'bg-red-50'}`}>
  <p>{monthlyBalance >= 0 ? '+' : ''}{formatSummaryAmount(Math.abs(monthlyBalance))}</p>
</div>
💡

String.prototype.startsWith() による月絞り込み： entry.date.startsWith('2026-03') は、日付文字列が "2026-03" で始まるものだけを取り出します。 filter((e) => e.date.slice(0, 7) === '2026-03') と書いても同じ結果ですが、 startsWith のほうが意図が明確です。

ヘルパー関数の解説

/**
 * 年・月・日を "YYYY-MM-DD" 形式の文字列に変換する
 * @param year - 年（4桁）
 * @param month - 月（0始まり。0=1月, 11=12月）
 * @param day - 日
 * @returns "YYYY-MM-DD" 形式の文字列
 */
function toDateStr(year: number, month: number, day: number) {
  return `${year}-${String(month + 1).padStart(2, '0')}-${String(day).padStart(2, '0')}`
  // padStart(2, '0'): 1桁の数字を "01" のように2桁にゼロ埋めする
  // 例: toDateStr(2026, 2, 5) → "2026-03-05"
}

/**
 * 指定した日付のエントリを配列から抽出する
 */
function getEntriesForDate(entries: Entry[], dateStr: string) {
  return entries.filter((entry) => entry.date === dateStr)
}

/**
 * 指定した日の支出合計と収入合計を計算する
 */
function getDayTotals(entries: Entry[], year: number, month: number, day: number) {
  const dayEntries = getEntriesForDate(entries, toDateStr(year, month, day))
  return {
    expense: dayEntries.filter((e) => e.type === 'expense').reduce((sum, e) => sum + e.amount, 0),
    income:  dayEntries.filter((e) => e.type === 'income').reduce((sum, e) => sum + e.amount, 0),
  }
}

/**
 * フォームの入力値からエントリオブジェクトを生成する
 * amount が空または 0 以下のときは null を返す（バリデーション）
 * @returns 生成した Entry、または無効な入力のとき null
 */
function buildEntry(
  selectedDate: string,
  amount: string,
  entryType: EntryType,
  category: string,
  note: string,
): Entry | null {
  if (!amount || Number(amount) <= 0) return null  // 空または0以下は無効
  return {
    id: Date.now(),  // 現在時刻をIDとして使う（シンプルな一意ID生成）
    date: selectedDate,
    type: entryType,
    category,
    amount: Number(amount),  // string → number 変換
    note,
  }
}

/**
 * 収支種別に対応するデフォルトカテゴリを返す
 * 支出/収入ボタン切り替え時に初期カテゴリを自動設定するために使う
 */
function resolveDefaultCategory(type: EntryType): string {
  return type === 'expense' ? EXPENSE_CATEGORIES[0] : INCOME_CATEGORIES[0]
}

入力フォームのハンドラ群

支出 / 収入ボタンを押したとき

「支出」ボタンを押すと handleSelectExpense が呼ばれます。 setEntryType('expense') で種別を更新すると同時に、 resolveDefaultCategory('expense') でカテゴリも支出用の先頭カテゴリに自動でリセットされます。 「収入」ボタンも同様で handleSelectIncome → resolveDefaultCategory('income') が動きます。 こうすることで「収入に切り替えたのに支出のカテゴリが残る」という違和感をなくしています。

}, [])

カテゴリを選んだとき

セレクトボックスを操作するたびに handleCategoryChange が呼ばれます。 ブラウザが発行する ChangeEvent の event.target.value に選んだカテゴリ名が入っているので、 それをそのまま setCategory に渡します。

const handleAmountChange = useCallback((event: React.ChangeEvent<HTMLInputElement>) => {
  setAmount(event.target.value)  // 文字列として保持（空文字もそのまま扱える）
}, [])

「保存」ボタンを押す（または Enter キー）とき

フォームは <form onSubmit={handleFormSubmit}> になっています。 「保存」ボタンのクリックでも Enter キーでも、handleFormSubmit が起動します。 まず event.preventDefault() でページリロードを防いだあと、handleSave() に委譲します。 handleSave は buildEntry(...) でエントリを生成し、 setEntries で配列に追加、最後に setShowForm(false) でフォームを閉じます。 

const handleFormSubmit = useCallback((event: React.SyntheticEvent) => {
  event.preventDefault()  // ブラウザのデフォルト送信（ページリロード）を止める
  handleSave()
}, [handleSave])

const handleSave = useCallback(() => {
  if (!selectedDate) return
  const entry = buildEntry(selectedDate, amount, entryType, category, note)
  if (!entry) return                           // buildEntry が null = 金額が無効
  setEntries((previous) => [...previous, entry])
  setAmount('')
  setNote('')
  setShowForm(false)                           // 保存後にフォームを閉じる
}, [selectedDate, amount, entryType, category, note])
📖

event.preventDefault() が必要な理由： HTML の <form> はデフォルトでページをリロードします。 Reactアプリではリロードすると state が全て消えてしまうため、 onSubmit で必ずこれを止めます。 <form onSubmit={handleFormSubmit}> にするだけで、 ボタンクリックと Enter キーの両方を一カ所でハンドルできます。

ヘルパー関数: formatAmount

セル幅に収まるよう、金額を短縮フォーマットに変換します。 1万円以上は「万」単位で表示し、小数第1位まで保持します（末尾の .0 は除去）。 

/**
 * カレンダーセル内に表示する金額を短縮フォーマットに変換する
 * 1万円以上は「万」単位で表示し、セル幅に収まるようにする。
 * 小数第1位まで表示（例: 1.3万、9.9万）、末尾 .0 は除去（例: 25万）。
 */
function formatAmount(amount: number): string {
  if (amount >= 10000) {
    return `${parseFloat((amount / 10000).toFixed(1))}万`
    // parseFloat で末尾の ".0" を除去: "25.0" → 25 → "25万"
    // 小数は残る:                       "1.3"  → 1.3 → "1.3万"
  }
  return amount.toLocaleString()  // 9,999 以下はそのまま: 3200 → "3,200"
}

// 表示例
// formatAmount(3200)   → "3,200"
// formatAmount(12500)  → "1.3万"
// formatAmount(250000) → "25万"
/**

20. AssetTrendChart コンポーネント

components/tabs/analytics/AssetTrendChart.tsx SVGグラフ（最も高度）

過去12ヶ月の資産推移を折れ線グラフ（SVG）で描画します。外部のグラフライブラリを使わず、SVGを直接生成しています。

SVGの座標系

// SVGの描画領域
const SVG_WIDTH  = 340  // SVGの幅（ピクセル）
const SVG_HEIGHT = 180  // SVGの高さ
const PADDING = { top: 16, right: 12, bottom: 28, left: 48 }
// ↑ left が大きいのはY軸ラベルのスペースを確保するため

// データの値範囲
const MIN_VALUE = 800000   // 80万円（Y軸の最小値）
const MAX_VALUE = 2800000  // 280万円（Y軸の最大値）

/**
 * データインデックスをSVGのX座標に変換する
 * @param index - データ配列のインデックス（0から始まる）
 * @param total - データの総数
 * @returns SVGのX座標（ピクセル）
 */
function toAssetX(index: number, total: number): number {
  const plotWidth = SVG_WIDTH - PADDING.left - PADDING.right
  return PADDING.left + (index / (total - 1)) * plotWidth
  // 例: 12点データの場合、index=0 → 左端、index=11 → 右端
}

/**
 * 資産の金額をSVGのY座標に変換する
 * SVGはY軸が下向き正なので反転が必要
 * @param value - 資産金額
 * @returns SVGのY座標（ピクセル）
 */
function toAssetY(value: number): number {
  const plotHeight = SVG_HEIGHT - PADDING.top - PADDING.bottom
  const ratio = (value - MIN_VALUE) / (MAX_VALUE - MIN_VALUE)
  return PADDING.top + plotHeight * (1 - ratio)
  // ↑ (1 - ratio) でY軸を反転: 値が大きいほどY座標が小さい（上）になる
}

グラデーション付き塗りつぶしエリアの生成

/**
 * 折れ線グラフの下部を塗りつぶすSVGパスを生成する
 * @param data - 資産データの配列
 * @returns SVGのパス文字列（d属性に渡す）
 */
function buildAssetAreaPath(data: AssetData[]): string {
  const total = data.length
  const bottomY = SVG_HEIGHT - PADDING.bottom  // グラフ底辺のY座標

  // 最初の点への移動
  let path = `M ${toAssetX(0, total)} ${bottomY}`  // 左下から開始

  // 全データ点を結ぶ
  data.forEach((point, i) => {
    path += ` L ${toAssetX(i, total)} ${toAssetY(point.asset)}`
  })

  // 右下に移動して閉じる
  path += ` L ${toAssetX(total - 1, total)} ${bottomY} Z`
  return path
}
{/* SVGでグラデーション定義 → パスに適用 */}
<defs>
  <linearGradient id="assetGradient" x1="0" y1="0" x2="0" y2="1">
    <stop offset="0%"   stopColor="#3b82f6" stopOpacity="0.3" />
    <stop offset="100%" stopColor="#3b82f6" stopOpacity="0"   />
  </linearGradient>
</defs>
<path d={buildAssetAreaPath(assetData)} fill="url(#assetGradient)" />

24. 使われているReactフック

useState — 状態の管理

const [state, setState] = useState(initialValue)
//         ↑現在の値   ↑更新関数      ↑初期値

// 例1: 文字列の状態
const [note, setNote] = useState('')

// 例2: 配列の状態（型付き）
const [entries, setEntries] = useState<Entry[]>(INITIAL_ENTRIES)

// 例3: null になりうる状態
const [selectedDate, setSelectedDate] = useState<string | null>(null)
📖

stateを更新すると何が起きる？ setState を呼ぶとReactはコンポーネントを再レンダリングします。 JSXを再評価して変化した部分だけをDOMに反映します（Virtual DOMの仕組み）。

useCallback — 関数のメモ化

const memoizedFn = useCallback(() => {
  // 処理
}, [dependency1, dependency2])
// ↑ 依存配列: ここに挙げた値が変わったときだけ関数を再生成する

// 使わない場合との違い
// ❌ これだとレンダリングのたびに新しい関数オブジェクトが生成される
const handleClick = () => doSomething()

// ✅ これなら同じ関数オブジェクトを使い回す（子コンポーネントの無駄な再レンダリング防止）
const handleClick = useCallback(() => doSomething(), [])
⚠️

CLAUDE.md の規約： このプロジェクトでは () => doSomething() のような関数式を Propsとして直接渡すことを禁止しています。 必ず useCallback() を使って渡すことが規約です。
